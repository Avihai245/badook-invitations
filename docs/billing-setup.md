# חיבור התשלומים (PayPlus)

המערכת מוכרת שלוש חבילות (חינם, Pro ו־Business, בחיוב חודשי) וחבילות הודעות וואטסאפ (100, 300 ו־1,000 הודעות, בתשלום חד־פעמי). התשלום עובר דרך **PayPlus**, חברת סליקה ישראלית (כרטיסי אשראי, Bit, Apple Pay ו־Google Pay, עם חשבוניות). פרטי הכרטיס מוקלדים בעמוד התשלום של PayPlus ולא מגיעים אלינו.

עד שהחיבור מוגדר, מסך החיובים מציג את החבילות ומסביר שהתשלום המקוון עוד לא הופעל, עם קישור ליצירת קשר.

## 1. מה צריך אצל PayPlus

1. חשבון סוחר ב־PayPlus (payplus.co.il), עם מסוף שמאפשר **חיוב חוזר (הוראת קבע באשראי)**.
2. **עמוד תשלום (Payment Page)** אחד: בממשק PayPlus → דפי תשלום → יצירת דף. ה־UID שלו הולך ל־`INVITES_PAYPLUS_PAGE_UID`.
3. **מפתחות API**: בממשק PayPlus → הגדרות → API. מקבלים `API Key` ו־`Secret Key`.
4. **חשבוניות**: בהגדרות הדף או המסוף מפעילים הפקת חשבונית/קבלה אוטומטית אחרי תשלום, כולל לחיובים החוזרים.

## 2. משתני הסביבה (Amplify → Hosting → Environment variables)

| משתנה | ערך |
|---|---|
| `INVITES_PAYPLUS_API_KEY` | ה־API Key |
| `INVITES_PAYPLUS_SECRET_KEY` | ה־Secret Key (גם לבדיקת החתימה על ההודעות מ־PayPlus) |
| `INVITES_PAYPLUS_PAGE_UID` | ה־UID של עמוד התשלום |
| `INVITES_PAYPLUS_SANDBOX` | `true` כדי לעבוד מול סביבת הבדיקות של PayPlus, `false` (ברירת המחדל) לסביבה האמיתית |
| `INVITES_PRICE_PRO` | מחיר Pro לחודש בשקלים, כולל מע״מ (ברירת מחדל `49`) |
| `INVITES_PRICE_BUSINESS` | מחיר Business לחודש (ברירת מחדל `149`) |
| `INVITES_WHATSAPP_PRICE_USD`, `INVITES_USD_TO_ILS` | מחיר הודעת וואטסאפ, שממנו מחושב מחיר חבילות ההודעות |

אחרי שינוי משתנים צריך build חדש (Redeploy).

## 3. איך זה עובד

1. המשתמש לוחץ על חבילה או על חבילת הודעות. המערכת רושמת את הרכישה ופותחת עמוד תשלום של PayPlus (`PaymentPages/generateLink`) עם מספר הרכישה שלנו. חבילה חודשית נפתחת כחיוב חוזר חודשי.
2. אחרי התשלום PayPlus מחזירה את המשתמש למסך החיובים, ובמקביל שולחת הודעת שרת אל `https://invitations.badooks.com/api/billing/payplus/callback`.
3. **לפני שהמערכת נותנת משהו, היא בודקת מול PayPlus** (`PaymentPages/ipn`) שהתשלום של אותו עמוד תשלום באמת עבר, ושהסכום נכון. הודעה מזויפת לא מקבלת כלום.
4. חבילה: מופעלת מיד, מתחדשת בעוד חודש, ומקבלת את הקרדיטים החודשיים שלה (Pro: 50, Business: 300). חבילת הודעות: הקרדיטים נוספים ליתרה.
5. **חידוש חודשי**: PayPlus מחייבת כל חודש ושולחת הודעה חתומה (כותרת `hash`, HMAC-SHA256 עם ה־Secret Key). המערכת מאריכה את החבילה בחודש ומוסיפה את הקרדיטים. חיוב שנכשל מסמן את החבילה ״לא שולמה״, והיא נשארת פעילה עוד 14 יום.
6. **ביטול**: המשתמש מבטל במסך החיובים. המערכת עוצרת את החיוב החוזר ב־PayPlus, והחבילה נשארת פעילה עד סוף התקופה ששולמה. אם העצירה ב־PayPlus נכשלת, נשלח מייל לתמיכה (`INVITES_SUPPORT_EMAIL`) כדי לעצור אותה ידנית.
7. **מעבר בין חבילות**: חבילה חדשה מחליפה את הקודמת, והחיוב החוזר הקודם נעצר.

## 4. בקרה

- כל אירוע תשלום נשמר בטבלה `billing_events` ומיושם פעם אחת בלבד, גם אם PayPlus שולחת אותו שוב.
- פעם ביום (עם הסיכום היומי של אישורי ההגעה) נשלח לתמיכה מייל על חבילות בתשלום שהחידוש שלהן לא הגיע יותר מ־3 ימים, כדי לבדוק אותן בממשק של PayPlus.
- אפשר לראות רכישות בטבלה `billing_checkouts` ותנועות קרדיטים בטבלה `credit_ledger`.

## 5. בדיקה

1. מגדירים `INVITES_PAYPLUS_SANDBOX=true` עם מפתחות של סביבת הבדיקות של PayPlus, ומבצעים רכישה עם כרטיס בדיקה של PayPlus.
2. בודקים שהחבילה עודכנה במסך החיובים, שהתשלום מופיע בהיסטוריה, ושהגיעה חשבונית.
3. מבטלים את המנוי ובודקים בממשק PayPlus שהחיוב החוזר הופסק.
4. עוברים לסביבה האמיתית: `INVITES_PAYPLUS_SANDBOX=false` עם המפתחות האמיתיים, ו־Redeploy.

בסביבת הפיתוח ובבדיקות האוטומטיות, `INVITES_BILLING_TEST_MODE=true` מחליף את PayPlus בעמוד תשלום לבדיקה של המערכת עצמה (שום כרטיס לא מחויב). **אסור להפעיל אותו בסביבה האמיתית.**
