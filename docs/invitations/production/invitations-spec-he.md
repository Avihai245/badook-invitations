# איפיון פיצ'ר: הזמנות דיגיטליות + אישורי הגעה (RSVP)
**סטנדרט מוצר v1 · מבוסס על ניתוח מקצה לקצה של KindlyRSVP · תמיכה מלאה בעברית (RTL) ובאנגלית**

---

## 0. תקציר

הזמנה דיגיטלית היא **עמוד מובייל אחד, חווייתי, בגלילה אנכית**: מעטפה סגורה → פתיחה מונפשת עם מוזיקה → Hero עם איור/וידאו → סקשנים של מידע (ספירה לאחור, מקום, לו"ז, הסעות, קוד לבוש, מתנות) → טופס אישור הגעה → פוטר.

ב-KindlyRSVP כל הזמנה נבנית **ידנית** על ידי מעצב (שירות "עשה זאת עבורי", ‎$395–$995). אצלנו המטרה הפוכה: **המשתמש בוחר תבנית, עורך את הפרטים בעצמו, רואה תצוגה חיה ומפרסם.** לכן הליבה היא הפרדה חדה בין:

| שכבה | מי שולט | מה היא מכילה |
|---|---|---|
| **Template** (תבנית) | אנחנו (צוות העיצוב) | צבעים, פונטים לכל כתב, מעטפה/חותם, וידאו Hero, איורים, מוזיקה, אנימציות, וריאנטים של סקשנים |
| **Invitation Document** (מסמך ההזמנה) | המשתמש (עריכה) | שמות, תאריך, מקומות, לו"ז, טקסטים בכל שפה, סקשנים פעילים וסדרם, הגדרות RSVP, התאמות צבע מוגבלות |
| **Renderer** (מנוע רינדור) | קוד | מקבל Template + Document + שפה → מרנדר את אותה הזמנה בעורך, בתצוגה מקדימה ובעמוד הציבורי |
| **Responses** (תשובות) | האורחים | אישורי הגעה, מספר משתתפים, העדפות תזונה, הודעות |

## 1. מה למדנו מ-KindlyRSVP

### 1.1 מודל עסקי ותפעול
- **טכנולוגיה:** כל הזמנה היא עמוד Framer נפרד (`/weddings/lev-zahav`, `/baby-showers/little-bloom`). הזמנת שירות דרך טופס Tally בן 9 שלבים. דשבורד RSVP ורשימת מתנות על Softr (`app.kindlyrsvp.com.au`).
- **חבילות:**

| | Classic ‏$395 | Signature ‏$595 | Bespoke ‏$995+ |
|---|---|---|---|
| סקשנים | 3 | 5 (+$15 לכל נוסף) | ללא הגבלה |
| מעטפה מונפשת + חותם | ✔ (חותם של התבנית) | חותם מותאם (ראשי תיבות) | ✔ |
| מוזיקה | של התבנית | של התבנית | מותאמת |
| RSVP + דשבורד | ✔ | ✔ + רשימת מתנות | ✔ + Planning Suite מלא |
| Save the Date | תוספת | כלול | כלול |
| סבבי תיקונים | 1 | 2 | ללא הגבלה |

- **תוספות:** שפה נוספת, סבב תיקונים נוסף, Save the Date, מהירות אספקה. **התאמות:** חותם שעווה מותאם, מוזיקה מותאמת, איור תמונה מותאם, **איור וידאו מותאם** (הופכים תמונה של הזוג לאיור צבעי מים מונפש — זה ה-Hero של Little Bloom).
- **שאלון ההזמנה אוסף:** סוג אירוע, שמות, תבנית, תאריך ושעה, מקומות (כמה אולמות), קונספט, חזון, "איזה רגש שהאורחים ירגישו", צבעים (HEX), כיוון סגנוני (ציורי / פרחוני / מודרני / קלאסי / יוקרתי), ראשי תיבות לחותם, שיר, תמונות, בחירת סקשנים.
- **קטלוג סקשנים שהם מוכרים:** Countdown, Timeline, Gift List, Transport, Activities, Menu, FAQ, Dress Code, Pre-Wedding, Our Story, Accommodation, Photos.
- **קטגוריות:** חתונות (9 תבניות), בייבי שאוור (3), ימי הולדת (3), טקסים דתיים (2 — בר מצווה וכו'), Save the Date (5). **15 שפות כולל עברית.**
- **Planning Suite:** ניהול RSVP ורשימת אורחים בזמן אמת, רשימת מתנות, סליקה (Stripe), ניהול תקציב.

**אנימציות שנמדדו:** Reveal בכניסה למסך — `opacity 0→1`, `translateY 40–150px→0`, בטקסטים גם `blur(10px)→0`. פונטים: כתב־יד תצוגתי (Tempting / Fantasia Script) + סריף אלגנטי (Cormorant / Bodoni Moda / Playfair) + Lora לטופס.

### 1.3 טופס RSVP — ההתנהגות המדויקת
- **"תגיעו?"** — רדיו כן/לא (חובה).
- **כן →** סטפר מבוגרים (ברירת מחדל 1) + סטפר ילדים (ברירת מחדל 0). לכל מבוגר נפתח כרטיס: שם פרטי, שם משפחה, טלפון, אימייל, **העדפות תזונה** (צ'קבוקסים) + הערות. לכל ילד: שם מלא, גיל, תזונה. כרטיס 1 = איש קשר ראשי.
- **אופציית כשרות:** טקסט הסבר ("כל האוכל כשר, מי שצריך כשר מהדרין — סמנו") + צ'קבוקס "kosher certified". ← **רלוונטי מאוד לשוק הישראלי.**
- **לא →** שם מלא, אימייל, טלפון, הודעה.
- **הודעה למארחים** (textarea) + כפתור שליחה.
- **שדות נסתרים:** אימייל הלקוח, שם הלקוח, סוג אירוע. **Honeypot** נגד ספאם (שדות website/company/subject נסתרים).
- כותרת המשנה יכולה לכלול דדליין ("…by May 1st").

### 1.4 פערים שאנחנו משפרים
1. **עריכה עצמית** במקום עבודת מעצב → אלפי הזמנות בלי צוואר בקבוק.
2. **מצב אחרי האירוע** — במקום "Time's Up!" הודעת תודה / הסתרת הספירה.
3. **כפתור מוזיקה** גלוי (אצלם אין) + כיבוד `prefers-reduced-motion`.
4. **Waze** לצד Google Maps (חובה בישראל), **תאריך עברי** מלא בגימטריה, **כשרות**, **הסעות**, **ביט/פייבוקס** במתנות.
5. **מתג שפות בתוך ההזמנה** (עברית/אנגלית) עם החלפת כיוון מיידית.
6. **עדכון תשובה** ע"י האורח, **תצוגת WhatsApp** (OG image) מושקעת, **QR**.
7. מפה שנטענת רק בלחיצה/גלילה (ביצועים).

## 2. עקרונות הסטנדרט
1. **Mobile-first, one page.** ‏90%+ מהאורחים פותחים מ-WhatsApp בטלפון. רוחב תוכן מקסימלי 560px, בדסקטופ ההזמנה ממורכזת.
2. **Template ≠ Content.** המשתמש לעולם לא נוגע ב-CSS. הוא עורך תוכן + בוחר מתוך אפשרויות שהתבנית מתירה (צבעי חותם, זוגות פונטים, מפתחות צבע מוגדרים).
3. **Renderer אחד** לעורך, לתצוגה המקדימה ולעמוד הציבורי — מה שרואים זה מה שמתפרסם.
4. **כל טקסט של משתמש הוא רב־לשוני** (`{he, en}`), כל טקסט מערכת מגיע ממילון.
5. **כיוון (dir) נגזר מהשפה**, לא מהתבנית. כל תבנית חייבת לתמוך בשני הכתבים.
6. **Draft / Published** — עורכים טיוטה, מפרסמים גרסה. הלינק לא משתנה לעולם; עדכון אחרי שליחה = פרסום מחדש.
7. **ביצועים ונגישות הם חלק מהעיצוב**, לא תוספת.
8. **לא מעתיקים** נכסים, איורים, טקסטים או שמות של KindlyRSVP — לומדים דפוסים, מייצרים תבניות מקוריות.

## 4. חוויית האורח — Flow ותזמונים

1. **טעינה:** מיד מוצג poster המעטפה (≤200KB, הפריים הראשון של וידאו הפתיחה, **בלי טקסט צרוב**). מעליו **שכבת חותם/מדליון/תגית ריקה** שנצבעת בצבע שהמשתמש בחר, ועליה המונוגרמה (SVG) — ככה ראשי התיבות ניתנים לעריכה לכל משתמש.
2. **Cover (וידאו כברירת מחדל):** אחרי 1.2 שניות מופיע "לחצו לפתיחה" + פעימה עדינה של החותם (scale 1→1.04, ‏2.4s). נגיעה / Enter / Space:
   - המוזיקה והווידאו מתחילים **בתוך אירוע הלחיצה** (דרישת iOS), למוזיקה fade-in של 1.5s.
   - בחצי השנייה הסטטית הראשונה של הווידאו החותם "יוצא": `crack` (נסדק לשניים) / `lift` (מתרומם) / `fade`.
   - הווידאו מתנגן (המעטפה נפתחת / השער נפתח / החבל מותר / הכרטיס נתלש). ‏600ms לפני הסוף — crossfade ל-Hero. **סה"כ ≈ 3–3.5s.**
   - Fallback: אין וידאו → אנימציית CSS 3D. `prefers-reduced-motion` → fade פשוט של 300ms. `?open=1` מדלג על המעטפה (לעורך ולצילומי מסך).
   - הנכסים והפרומפטים להפקה: `invitation-templates-kit-he.md`.
3. **Hero:** ‏`100svh`, מדיה `object-fit: cover` לפי נקודת מוקד. כניסה מדורגת: שורת פתיחה 0ms → שמות +150ms → קו (scaleX 0→1) +300ms → תאריך +450ms; כל אחד 900ms מ-`opacity 0, blur 10px, y 16px`.
4. **גלילה:** כל סקשן נחשף פעם אחת כש-20% ממנו בתצוגה: `y 40px→0`, `opacity 0→1`, ‏800ms, ‏ease `[0.22,1,0.36,1]`, ילדים מדורגים 80ms.
5. **כפתור מוזיקה** צף בפינה (`inset-inline-end`), מופיע אחרי פתיחה. מושהה כשהטאב מוסתר.
6. **מתג שפה** (אם יש יותר משפה אחת) בפינה העליונה: `EN | עב` — מחליף טקסטים + `dir` בלי רענון ושומר מיקום גלילה.
7. **Countdown:** ‏4 תאים, ספרות `tabular-nums`. ב-RTL "ימים" מימין. לפני האירוע סופר; מתחילת האירוע ועד יום אחריו — הטקסט "אחרי האירוע"; אחר כך הסקשן מוסתר.
8. **Venues:** כפתור מפות → Google Maps (לפי קואורדינטות או חיפוש). Waze → `waze.com/ul?ll=…&navigate=yes`. יומן → תפריט Google / Apple (.ics) / Outlook, עם שעת התחלה/סיום ואזור זמן נכונים. המפה המוטמעת נטענת Lazy (placeholder סטטי עד שנכנסים לתצוגה).
9. **RSVP:** ראה סעיף 6.
10. **Footer:** שמות, תאריך, הורים, שורת סיום, קרדיט (ניתן להסרה בתוכנית בתשלום).

## 5. העורך (Editor) — איך המשתמש יוצר ועורך

### 5.1 Flow יצירה
1. **גלריית תבניות** — סינון לפי סוג אירוע, כרטיס עם וידאו preview בטלפון, כפתור "תצוגה חיה".
2. **Wizard קצר (3 מסכים):** סוג אירוע → שמות + תאריך + שעה → שפות (עברית / אנגלית / שתיהן + ברירת מחדל). נוצרת טיוטה עם **תוכן ברירת מחדל מלא** לפי סוג האירוע ושפה (לו"ז טיפוסי, טקסטים, סקשנים מומלצים).
3. **עורך מלא:**
   - **דסקטופ:** 3 עמודות — רשימת סקשנים (גרירה לשינוי סדר, הפעלה/כיבוי, הוספה מהקטלוג) | טופס עריכה של הסקשן הנבחר | **תצוגה חיה בתוך מסגרת טלפון**.
   - **מובייל:** טאבים "עריכה" / "תצוגה".
   - **לחיצה על אלמנט בתצוגה** → קופץ לשדה שלו בטופס.
   - **שדות רב־לשוניים:** כששתי שפות פעילות, כל שדה טקסט מציג לשוניות `עב | EN` עם סימון "חסר תרגום". כיוון ה-input תואם ללשונית.
   - **עיצוב:** בחירת זוג פונטים, צבע חותם (מתוך רשימת התבנית), מונוגרמה, התאמת מפתחות צבע שהתבנית מתירה — עם בדיקת ניגודיות (אזהרה מתחת ל-4.5:1).
   - **מדיה:** העלאת תמונה/וידאו ל-Hero עם בחירת נקודת מוקד. וידאו: MP4 עד 15MB ו-20 שניות, poster נוצר אוטומטית מהפריים הראשון.
   - **מוזיקה:** ספריית שירים ברישיון + העלאת MP3 (עם אישור זכויות).
4. **שמירה אוטומטית** (debounce ‏800ms) לטיוטה. תג "שינויים שלא פורסמו".
5. **פרסום:** ולידציה (שגיאות חוסמות, אזהרות לא) → בחירת slug → הלינק נוצר. מסך שיתוף: העתקת לינק, **כפתור WhatsApp**, **QR להורדה**, תצוגה מקדימה של הכרטיס כפי שיופיע ב-WhatsApp.
6. **עדכון אחרי שליחה:** עורכים טיוטה → "פרסום עדכון" → אותו לינק, גרסה חדשה (היסטוריית גרסאות + שחזור).

## 6. RSVP ודשבורד

### 6.1 טופס (צד אורח)
- **כן:** סטפרים (מבוגרים 1..max, ילדים 0..max — מוסתר אם `askChildren=false`). כרטיס לכל משתתף. איש קשר ראשי: שם פרטי + משפחה + טלפון (חובה לפי הגדרה) + אימייל (חובה לפי הגדרה). מבוגרים נוספים: שם פרטי + משפחה. ילדים: שם מלא + גיל (0–17).
- **תזונה:** `ללא העדפות` מבטל את כל השאר (ולהפך). אלרגיה לאגוזים / אחרת → הערות חובה.
  מפתחות: `none, kosher, kosher_mehadrin, vegetarian, vegan, gluten_free, dairy_free, pescatarian, nut_allergy, other_allergy, kids_meal`.
- **שאלות מותאמות:** טקסט / בחירה / כן־לא (למשל "מצטרפים להסעה?").
- **לא:** שם מלא + טלפון **או** אימייל + הודעה.
- **טלפון/אימייל** תמיד `dir="ltr"` גם בעמוד עברי, מיושרים לצד תחילת העמוד. נרמול ל-E.164 (ברירת מחדל IL בעברית).
- **אחרי שליחה:** הטופס מתחלף בהודעת הצלחה + "הוספה ליומן" + "עדכון התשובה שלי" (טוקן עריכה נשמר בדפדפן).
- **אחרי הדדליין:** הודעת "אישורי ההגעה נסגרו".
- **הגנות:** Honeypot, זמן מילוי מינימלי 3 שניות, Rate limit לפי IP, ולידציה בשרת (לא סומכים על הלקוח).

### 6.2 דשבורד (צד מארח)
- **KPI:** תשובות, מגיעים (מבוגרים / ילדים / סה"כ ראשים), לא מגיעים, סיכום תזונה (כמה כשר מהדרין, צמחוני וכו'), שאלות מותאמות (כמה להסעה מת"א).
- **טבלה:** חיפוש, סינון (מגיע/לא), פתיחת תשובה מלאה, **ייצוא CSV עם BOM** (כדי שעברית תיפתח נכון ב-Excel) / Excel.
- **התראות:** מייל למארח על כל תשובה או סיכום יומי.
- **Realtime** (אופציונלי): עדכון חי.
- **שלב 2:** רשימת מוזמנים + לינק אישי לכל אורח (`?g=token`) עם שם ממולא ו"שמרנו לכם X מקומות".

## 7. עברית / RTL — כללי ברזל
1. `<html lang dir>` נקבעים לפי השפה הפעילה. בהזמנה דו־לשונית — מתחלפים בזמן אמת.
2. **CSS לוגי בלבד:** `margin-inline-start`, `padding-inline-end`, `inset-inline-end`, `text-align: start`. ב-Tailwind: `ms-/me-/ps-/pe-/start-/end-`. אסור `left/right` קשיח.
3. **אייקונים כיווניים** (חצים, שברון) מתהפכים ב-RTL; סיכה/שעון/לב — לא.
4. **שורות אופקיות** (לו"ז, תאי ספירה) זורמות מימין לשמאל ב-RTL — זה נכון, לא לתקן.
5. **Bidi:** שמות באנגלית בתוך טקסט עברי ולהפך → `<bdi>` / `unicode-bidi: isolate`. טלפון, אימייל, שעות, URL → `dir="ltr"`.
6. **פונטים לכל כתב:** לכל תבנית זוג פונטים עם גרסה לטינית + עברית (פונטי כתב־יד לטיניים לא כוללים עברית!). עבריים מומלצים (Google Fonts): Bellefair, Frank Ruhl Libre, Noto Serif Hebrew, Suez One, Amatic SC, Heebo, Assistant, Rubik. אפשר להוסיף פונטים מסחריים ברישיון. טעינה עם `unicode-range` כדי לא להוריד כתב מיותר.
7. **תאריכים:** לועזי דרך `Intl.DateTimeFormat('he-IL')` → "יום חמישי, 17 ביוני 2027". **עברי בגימטריה** דרך `@hebcal/core` → "י״ב בסיון תשפ״ז". מצב `eve` לאירוע ערב: "אור לי״ג בסיון" (התאריך העברי מתחלף בשקיעה).
8. **שעות:** עברית 24h (‏19:30), אנגלית 12h (‏7:30 PM) — ניתן לשינוי.
9. **ספרות:** תמיד ספרות "מערביות" (0-9).
10. **רבים:** `Intl.PluralRules`; בעברית fallback ל-`other` ("ימים").
11. **תוכן ישראלי מובנה:** חופה וקידושין, קבלת פנים, הסעות, כשרות / מהדרין, ביט / פייבוקס, Waze, שמות הורים, תאריך עברי, קוד לבוש.

## 8. שיתוף, SEO ופרטיות
- **URL:** ‏`/i/{slug}` (+ `?lang=en`). ‏slug: אותיות לטיניות קטנות, ספרות, מקף, 3–60 תווים. הצעה אוטומטית מהשמות (תעתיק).
- **OG Image 1200×630** נוצרת בפרסום: פלטה של התבנית + שמות + תאריך. **חובה לבדוק שעברית מרונדרת נכון** (ספריות OG מסוימות חלשות ב-RTL — fallback: צילום מסך של עמוד `/og` בצד שרת).
- `noindex` כברירת מחדל (הזמנות פרטיות).
- **QR** להורדה (PNG/SVG).
- **פרטיות:** תשובות גלויות רק לבעלי ההזמנה. מחיקת הזמנה מוחקת את כל התשובות.

## 10. איך מגדירים תבנית חדשה (Template Manifest)
כל תבנית = קובץ manifest + תיקיית נכסים. הצ'קליסט לצוות העיצוב:
- [ ] פלטה (8 טוקנים: `bg, surface, ink, inkMuted, accent, accentInk, line, heroText`) + אילו מפתחות המשתמש רשאי לשנות.
- [ ] 1–3 זוגות פונטים — **לכל אחד גרסה לטינית + עברית**.
- [ ] Cover: סגנון (`envelope_seal` / `gatefold` / `pouch` / `swaddle` / `ticket` / `ribbon`), poster + וידאו פתיחה (9:16, ורצוי גם 16:9), שכבת חותם ריקה + צבעים מותרים + אפקט טקסט + יציאה, פונט מונוגרמה לכל כתב.
- [ ] Hero: וידאו + poster + צבע שכבה + ברירת מחדל לעוצמה.
- [ ] 3–8 איורים (מפרידים / איורי סקשן) — PNG/WebP שקופים, בסגנון אחיד.
- [ ] מוזיקה ברישיון מסחרי.
- [ ] וריאנטים לסקשנים + סדר ברירת מחדל.
- [ ] תוכן ברירת מחדל לכל סוג אירוע שהתבנית תומכת בו, **בעברית ובאנגלית**.
- [ ] בדיקה: שם ארוך בעברית, שם ארוך באנגלית, 4 מקומות, 10 פריטי לו"ז, ללא מדיה, מצב כהה של המכשיר (אין להסתמך עליו — ההזמנה תמיד בצבעי התבנית).

## 11. מודל נתונים (תמצית)
- `invitation_templates` — id, manifest (jsonb), פעיל, סדר.
- `invitations` — owner, template_id, slug ייחודי, status (`draft/published/archived`), `draft` (jsonb), `published` (jsonb), published_at, version.
- `invitation_versions` — היסטוריית פרסומים.
- `rsvp_responses` — invitation_id, attending, locale, שם ראשי, טלפון, אימייל, מבוגרים, ילדים, הודעה, answers (jsonb), edit_token_hash.
- `rsvp_attendees` — response_id, kind (adult/child), שמות, גיל, טלפון, אימייל, dietary[], הערות.
- **RLS:** בעלים מנהלים את ההזמנות שלהם; הציבור קורא רק גרסה מפורסמת דרך RPC; שליחת RSVP רק דרך Endpoint בשרת עם ולידציה.

> החוזים המלאים (TypeScript, SQL, API), דוגמאות JSON מלאות בעברית ובאנגלית ו-Acceptance Criteria — בקובץ הפרומפט `claude-invitations-build-prompt.md`.
