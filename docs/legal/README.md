# Legal documents — version 2 (compliance programme)

This folder is the owner's map of the legal, privacy, consumer-protection, accessibility and
user-generated-content programme for Badook Invitations. **Nothing in it is legal advice or a
certification.** Every matter that needs an Israeli lawyer, a regulator filing or an owner decision is
a numbered decision record in [`decision-records.md`](decision-records.md).

| File | What |
| --- | --- |
| [`decision-records.md`](decision-records.md) | open questions for the owner / counsel, with the facts, options and the proposal |
| [`evidence-matrix.md`](evidence-matrix.md) | requirement → basis → implementation → test evidence → status |
| [`processors.md`](processors.md) | processors, data flows and transfers (privacy law, Regulation 15, transfer regulations) |
| [`database-assessment.md`](database-assessment.md) | registration / notification / DPO / security-level applicability assessment + database definition skeleton |
| [`security-findings.md`](security-findings.md) | what was tested, what was found, what was fixed and what is left |
| `review/` | the six documents exported to Markdown (Hebrew + English) for counsel — generated by `npm run legal:export` |

## The six documents

Terms of use, privacy policy, cookie policy, accessibility statement, refund and cancellation policy,
event gallery and user-generated content rules. Their texts live in `src/features/legal/`:

- `v1/` — the text that was live before this programme. **Frozen**: `tests/unit/legal-docs.test.tsx`
  compares each file with a SHA-256 manifest (`tests/fixtures/legal-v1.sha256.json`).
- `v2/` — the new texts (Hebrew + English in one function per document).
- `registry.ts` — every version of every document; `versionInForce()` chooses what the stable route shows.
- Stable routes: `/terms`, `/privacy`, `/cookies`, `/accessibility`, `/refunds`, `/gallery-rules`.
  Every version keeps a permanent address, `/legal/<document>/<version>`; a page shows its version, its
  effective date, an "earlier version" notice and the version history.

## Nothing is published until the owner switches it on

Version 2 and every behaviour that belongs to it (first-upload notice, "Report content", the privacy
request form, acceptance records, the checkout disclosure, the new footer links) are **off** until:

1. `INVITES_LEGAL_V2=true`, **and**
2. the operator's details are complete: `INVITES_LEGAL_NAME`, `INVITES_LEGAL_ID`, `INVITES_LEGAL_ADDRESS`,
   `INVITES_SUPPORT_EMAIL`, and the effective date `INVITES_LEGAL_V2_EFFECTIVE` (`YYYY-MM-DD`).

If any is missing the switch has no effect (`src/features/legal/readiness.ts`) — a blank or invented
identity is never published. Optional: `INVITES_PRIVACY_EMAIL` (defaults to the support address),
`INVITES_ACCESSIBILITY_*`, and `INVITES_ACCESSIBILITY_REVIEW_DATE` (set it **only** when a manual review
with assistive technology really took place — otherwise the statement says none is reported).

Before switching on: read DR-01 (who is the operator), DR-02 (the 14-day notice to hosts the current
terms promise), DR-03 (face search) and DR-04 (refund wording), apply the migration
`supabase/migrations/20261013000100_legal_compliance.sql` (additive; no data is changed), and have
counsel review `review/`.

## Changing a document later

A change to a text that was in force is a **new version**: add `v3/…`, add the entry in `registry.ts`,
move `LEGAL_VERSION` in `versions.ts`, leave earlier files untouched. Evidence already recorded keeps the
version number it was recorded with; new versions are never treated as accepted by anyone who did not
accept them.

## Tests

`npx vitest run tests/unit/legal-docs.test.tsx` (documents, versions, readiness), `npm run test:db` (RLS,
reports, requests, acceptance, cancellation), plus the feature tests listed in the evidence matrix.
